V189 - DATABASE CANONICAL SYNC

Vì sao V188 có thể lệch:
1. Pull Cloud trước push pending và không pull lại sau push.
2. sales/sale_items/stock_transactions có giới hạn; Supabase cũng có max rows theo request.
3. Storage Revision không phải transaction của database nghiệp vụ.

V189:
- Push pending trước.
- Pull lại toàn bộ database sau push.
- Tất cả bảng được đọc bằng pagination 1000 dòng/trang cho đến hết.
- Local-only state dùng bảng app_sync_state + RPC compare-and-swap.
- Hai thiết bị commit cùng lúc: chỉ một commit thắng; máy còn lại tự pull revision mới, merge và retry.
- Sau commit app pull canonical state để xác minh.
- Sau đó pull database nghiệp vụ lần cuối.
- Chỉ hiện “Đã đồng bộ hoàn toàn • Rev N” khi:
  + DB online,
  + không còn pending,
  + CAS canonical đã hội tụ.

CÀI ĐẶT:
1. Supabase -> SQL Editor -> New query.
2. Mở SUPABASE-V189-TRANSACTIONAL-SYNC.sql.
3. Copy toàn bộ -> Run.
4. Deploy V189 lên GitHub Pages.
5. Mở tất cả thiết bị, reload/cập nhật app.
6. Bấm Đồng bộ ngay ở từng thiết bị một lần.

LƯU Ý:
- V189 vẫn giữ backup mã hóa Storage và QR pairing.
- app_sync_state lưu payload đã mã hóa client-side.
- Không xóa bucket lat-yen-backups.
